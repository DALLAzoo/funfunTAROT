# AD4 — 세로 결과 설명창 좌우 글자 여백 수정 · 2026-11-13

## 출발점
- 직전 기준 ZIP: `AD4_full_20261113.zip` (세로 스마트폰 / 가로 PC 비율 연속 통합 시험본).
- 사용자가 제공한 iPad mini, iPad Pro 13, Surface Pro 10, Galaxy A55 결과 화면 캡처.

## 원인 및 변경
- 기존 일반 세로 CSS `padding:clamp(12px,1.4vw,18px)`와 좁은 세로 @container `padding:11px 13px`가 좌우 여백을 다르게 적용.
- `23-portrait-responsive-scale.css` 안의 설명창 좌우 여백 규칙을 `padding-inline:clamp(14px,var(--portrait-reading-size),20px)`로 통일.
- 작은 세로 화면의 위아래 여백 11px은 그대로 유지.
- 스크롤바가 한쪽 공간만 소비하지 않도록 `scrollbar-gutter:stable both-edges` 적용. 화면에 스크롤바 겹침 방식이 사용되는 경우에는 브라우저가 해당 속성을 다르게 처리할 수 있음.

## 변경 범위
- 기존 파일 수정: `css/screen/23-portrait-responsive-scale.css`, `CHANGELOG.md`.
- 신규 보고서: `docs/AD4_세로설명창_좌우여백_수정검증_20261113.md`.
- 설명창 크기, 카드 비율·크기, 제목·버튼, 셔플·부채꼴·선택·공개 JS 및 CSS 규칙은 변경하지 않음.

## 검증
- 원본 대비 ZIP 구성 파일 해시 비교 및 압축 검사.
- 실제 사이트 CSS의 전체 import 순서를 보존해 브라우저에 인라인 로드한 DOM/스타일 시험(실제 사이트 JS 실행 아님): 아래 6개 화면에서 비교.
- Galaxy A55 세로 360×800: 좌우 13px → 14px / 14px.
- iPad mini 세로 768×1024: 좌우 12px → 17.5px / 17.5px.
- Surface Pro 10 세로 960×1440: 좌우 13.4px → 19.3px / 19.3px.
- iPad Pro 13 세로 1032×1376: 좌우 14.4px → 20px / 20px.
- 갤럭시 가로 800×360 및 iPad mini 가로 1024×768: 변경 없음.
- 설명창 너비·카드 크기·버튼 좌표는 검사한 화면에서 전후 동일. 스크롤 가능한 화면에서도 문장 영역 좌우 여백은 동일.
- 실제 기기(Chrome 개발자 도구가 아닌 기기)에서의 시각 검증과 전체 셔플 플로우는 미수행.
