## 발견 원인 및 사용자의 수정 의도

첫 카드뭉치 및 부채꼴은 700px를 지나면 모바일 세로 기본값에서 터치 태블릿 세로 기본값으로 단번에 전환되었다. `responsiveDesignMetrics()`는 연속화됐지만, 각 진행 단계 카드 너비를 정하는 `calculatePreferredStageSize()`에는 별도 불연속이 있었다. 사용자는 기존 디자인/모션을 보호하면서 가로가 1px 달라질 때 카드가 20~30px씩 뛰는 문제부터 고치기로 승인했다.

## 수정 방법

`isTouchPortrait()`인 경우에 한해 `idle/shuffle/selection/transition` 네 단계의 카드 기본 크기를 원래 모바일·태블릿 계산으로 동시에 구한 다음 **너비 640~760px 구간에서 선형 연결**한다. 640px 이하 및 760px 이상의 결과는 기존 공식과 동일하다. 700px의 기존 **배치 분기 자체는 그대로** 두었다. 화면 높이와 stage 높이에 대한 원래 제한 및 `stageSize()` 선택 단계의 잘림 방지 계산도 유지한다. 새로운 기기명 조건이나 CSS 덮어쓰기 추가 없음. `result`는 앞서 해결한 연속 크기 계산을 그대로 유지한다.

## 검증

- Node JS 문법 검사 통과 (`node --check`).
- 터치 세로 가정에서 8가지 높이(640,768,844,940,1024,1180,1366,1499), 너비 320~1199 범위 중 실제 세로 조건(너비<높이)의 연속 정수 너비를 검사.
- `idle/shuffle/selection/transition/result` 크기 계산 역전 **0건** (검사 조건에 한정).
- 너비 <=640 또는 >=760인 화면의 단계별 계산값이 기존 ZIP과 다르게 나온 경우 **0건** (검사 조건에 한정).
- 결과 화면 카드 크기 계산은 모든 검사 조건에서 변경 없음.
- 화면 배치 CSS·다른 JS 파일·애니메이션 키프레임 변경 없음.

## 미검증·남은 조사

- 실브라우저 구동 검증 불가: 실행 환경에 Playwright 브라우저 바이너리가 없음. 실제 기기에서의 카드 겹침/잘림·화면 회전·셔플→부채꼴→공개 연속성은 미검증.
