## 구현한 흐름

1. 22장 전체를 준비하고, 이미지 load/decode 완료 후 덱을 교체한다.
2. 카드들이 넓은 x/y/z 공간으로 분리된다. 전경·후경을 통과하며 서로 다른 위상·반경·기울기로 섞인다.
3. 카드가 중앙으로 감속·응축되고 기존 마법 파동과 연결된다.
4. 파동과 같은 진행률로 선택용 3장이 부채꼴로 펼쳐진다. 물리적 기본 크기는 같고, 중앙 카드의 z 깊이로 시각적 크기가 달라진다.
5. 선택 대상 20장 안에서 좌우 드래그·화살표·키보드로 순환한다. 기본 화면에는 3장만 표시한다.
6. 선택한 카드가 앞으로 부상한다. 다른 카드는 뒤로 물러나고 짧은 에너지 집중이 이어진다.
7. 같은 카드 뒷면을 가진 전환 카드가 실제 화면 크기에 맞춰 확대된다.
8. 전환 카드의 경계가 화면 전체를 덮은 것을 확인한 뒤 결과 장면을 표시한다.
9. 카드가 결과 위치로 줄어들어 들어온 뒤 뒤집히며 공개된다. 결과 공개 방식은 설정에서 대안과 비교할 수 있다.

## 셔플 동선과 재질

카드 scale은 셔플 구간에서 1로 유지한다. 무작위 확대/축소가 아니라 CSS perspective와 z 위치가 겉보기 크기를 만든다. 기본 perspective 1000px에서 가까운 깊이는 약 +480px, 먼 깊이는 약 -340px이며 투영 배율 차이는 약 2.5배다. 전경 카드가 무대 일부를 벗어나는 것은 의도된 연출이다.

서로 반대 위치를 지나는 카드들을 조합해 덱 전체를 반복적으로 위아래 이동시키는 궤도를 만들지 않았다. 카드별 궤도는 서로 다르며 중앙 모임으로 연속적으로 연결된다. 설정 장수가 바뀌면 카드 수에 따라 위상·반경 분포를 다시 계산한다.

원본 PNG에 합성하지 않고 카드 뒤의 얇은 평행 레이어, 측면 테두리, 그림자로 두께를 표현했다. 새틴 느낌은 주로 얇은 가장자리 하이라이트에 제한했다. 카드 면 전체에 광택색을 씌우지 않는다. 이것은 가벼운 CSS 3D 표현이며 완전한 PBR 재질·메시 렌더러는 아니다.

## 파동 보존과 연결

기존 Canvas 두 층·원형 파동·잔광 구조를 활용했다. 새 셔플 시간에 맞춰 응축 시점을 설정에서 읽는다. 파동은 첫 번째 펼침 카드의 실제 WAAPI 시계를 읽고, 카드와 같은 pressureProgress 및 81개 키프레임 보간값을 사용한다.

선택 단계 크기는 셔플 단계와 독립이다. 중앙 모임 직후 갑자기 크기를 교체하지 않고, 3장 펼침 구간에서 셔플 크기→선택 크기를 같이 보간한다. 선택 카드의 에너지 집중은 이전 셔플 효과를 정리한 뒤 시작한다.

## 20장 구성: 시험안과 최종 정책 구분

기준 데이터는 메이저 22장이다. 초기 시험은 전체 데이터를 섞어 20개의 서로 다른 ID를 선택하는 `trial-uniform-subset` 모드다. 고정으로 제외하는 두 장은 없다. 이 방식은 화면·입력·연결을 시험하기 위한 임시 동작이며 최종 정책이 아니다. 화면에도 이 사실을 표시한다.

최종안 후보와 미확정 항목은 `설계_미확정사항.md`에 구분했다. 명시된 20개 ID로 동작하는 모드도 구현했다. 78장 보관 계획은 현재 20장 선택 수와 연결해 고정하지 않았다.

## 순환·입력·데이터 연결

- 20개 데이터와 카드 DOM을 ID로 연결한다. ID는 `major-00`~`major-21`이며 결과에도 그대로 전달한다.
- 선택 화면에는 기본 3개만 활성화한다. 이동 시 기존 카드가 빠진 자리에 다음 카드가 들어오며 동시에 활성 표시되는 수를 넘기지 않는다.
- 첫 카드 이전은 마지막 카드, 마지막 다음은 첫 카드다.
- 드래그 거리 기준을 넘으면 탐색으로 처리하고, 드래그 직후 생성되는 클릭은 선택으로 처리하지 않는다.
- 수직 움직임은 페이지 스크롤과 충돌하지 않도록 취소하며 CSS touch-action:pan-y를 사용한다.
- 이미지 준비·선택 전환 중 입력을 막는다. 파기된 순환 객체가 새 셔플의 배치를 덮어쓰지 않도록 한다.
- 키보드 포커스는 카드 밖의 선으로 표시한다. 포커스된 카드에서 좌우 방향키로 탐색하고 Enter/Space로 선택할 수 있다.

## 초록색 카드 면 발광: 사실·조치·미확정

### 코드에서 확인한 사실

기준 CSS에는 `.tarot-card.selectable:hover .card-face { filter:brightness(1.2) }`가 있었다. 이는 가장자리가 아닌 카드 면 전체의 밝기를 바꾼다. 기준 JavaScript에는 호버할 때 카드 면을 초록색으로 바꾸는 별도 처리가 없었다. 터치 하이라이트 색상을 명시적으로 해제하는 코드도 없었다.

이 사실만으로 사용자의 기기에서 발생한 **초록색 면 덮임의 정확한 원인까지 확정할 수는 없다.** 브라우저의 터치 하이라이트나 다른 통합 CSS의 영향은 후보이며 미확정이다.

### 수정

- 카드 면의 호버 밝기 필터 제거.
- 카드 면 filter:none 유지, 버튼의 hover/active/focus 배경 투명 처리.
- -webkit-tap-highlight-color:transparent 지정.
- 라벤더 발광은 카드 바깥 pseudo-element의 테두리와 외부 box-shadow로만 표현. 카드 면 전체를 다른 색으로 바꾸지 않음.
- 키보드 focus-visible 표시 유지.

실제 Chrome PC의 선택 화면에서 세 카드 모두 opacity=1, faceFilter=none, 물리적 너비 210px를 확인했다. 원래 현상의 실제 휴대폰 재현·비교는 미검증이다.

## 발견하여 조정한 항목

- 모바일 선택 화면의 바깥 카드가 잘리는 것을 확인해 회전된 카드 폭과 원근 투영을 반영하여 간격을 자동 계산하도록 수정했다.
- 셔플→선택의 단계별 크기가 갑자기 바뀌지 않도록 펼침 중 크기를 함께 보간했다.
- 새 셔플 중 오래된 순환 작업이 배치를 덮어쓸 가능성을 막았다.
- 최초 뒷면 로딩 실패 시에도 재시도할 수 있게 했다.
- 결과 화면에서 다시 섞기를 누른 동안 버튼을 비활성화하고, 로딩 실패 시 결과 화면에 안내하도록 했다.

## 보존과 미검증

원본 GitHub·배포 사이트·기준 ZIP은 보존했다. 기준 ZIP 안의 카드 로딩·해독 대기와 불투명 처리, 8종 원본 PNG를 유지했다.

상담·예약은 기준 ZIP에 없어 기능 실행을 검증하지 못했다. 원본 사이트에는 작업을 반영하지 않았다.

실제 Android/iOS·Safari·Firefox, 느린 네트워크, 터치 하이라이트 재현, 78장 전체 자산, 저사양 FPS·발열·긴 반복 실행, 전환 도중 화면 회전, 프레임별 덜컥거림 영상 비교는 미검증이다.

기본 화면·이름·기호 시연 결과는 작동하지만 **실제 타로 앞면 이미지의 기본 공개는 자산 등록 전이므로 미완료**다. 20장 구성 정책과 최종 공개 방식도 아직 확정하지 않았다.
