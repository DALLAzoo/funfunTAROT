# AD4 — 소형 태블릿 세로 결과 화면 UI 균형 조정 (2026-11-12)

## 문제와 사용자 요청
- 기준: AD4 2차 공통 비례 설계 전체 시험본.
- 사용자 관찰: 스마트폰·PC·다른 태블릿·폴더블 배치는 만족하지만, 아이패드 미니 세로 화면의 **전체 UI 비율**이 어색하고 카드 앞면이 지나치게 커 리딩 문구 공간이 부족함.
- 이번 수정은 카드만 별도로 꾸미거나 제목·버튼을 새로 배치하지 않음. 기존 화면 구성과 가독성 관계를 회복하는 범위로 한정.

## 코드 변경 — 기존 계산만 직접 수정
- 대상: `js/settings/config/config.js` → `adaptiveTabletSize()`의 `phase==='result'` 및 `isTabletPortrait()` 계산.
- 기존: 짧은 화면 세로도 태블릿 너비 기반 선호값(약 322~333px 카드 너비)을 대부분 그대로 적용하여 앞면 카드가 화면 높이의 약 49~56%를 점유함.
- 변경: 화면 너비와 세로 공간이 모두 작은 터치 태블릿 세로에서만, 기존 제목·리딩창·하단 버튼 공간을 고려한 **카드 높이 상한**을 적용. 태블릿 크기가 커질수록 이 보정이 연속적으로 사라짐.
- 새 CSS 미디어 규칙, 기기명 조건, CSS 우선순위 덮어쓰기 추가 없음. 기존 가로 및 PC·스마트폰 계산 경로 유지.
- 결과 카드 폭·높이는 기존 공개 코드가 `stageSize('result')` 값을 사용하므로 함께 갱신됨. 카드 종횡비는 유지하며 공개 이동·뒤집기 시간이나 셔플·부채꼴은 변경하지 않음.

- 위 8개 화면에서 `idle`, `shuffle`, `selection`, `transition` 단계 카드 크기 계산값은 모두 전후 동일.
- 태블릿 세로 결과 화면의 상단 제목·문구 글꼴·버튼 위치와 크기 CSS는 변경하지 않음. 해당 화면에서 **전체의 상대 비율**은 카드 높이가 줄고 읽기 공간이 늘어나 균형이 달라짐.
- 직접 확인하지 않은 임의 기기 조합은 영향 없음으로 단정할 수 없음. 이 계산식은 화면의 실제 폭/높이에 따라 작동하므로 아이패드 미니와 유사한 치수의 소형 터치 태블릿에도 적용됨.

## 검증 상태
- Node.js의 실제 전후 JS 모듈을 실행하여 8개 대표 크기 결과와 나머지 단계 불변을 검증함.
- `node --check` 통과.
- 브라우저 자동 실행은 실행 환경에서 `net::ERR_BLOCKED_BY_ADMINISTRATOR`로 차단되어 실화면·아이패드 실제 기기 검증은 **미완료**.
