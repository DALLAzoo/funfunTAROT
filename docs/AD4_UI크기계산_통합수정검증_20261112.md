# AD4 — UI 크기 계산식 통합 · 2026-11-12

## 기준 및 범위
- 기준 원본: `InBetweenShift_AD4_아이패드미니세로_UI비율조정_전체시험본_20261112.zip`.
- 사용자가 만족한 스마트폰·태블릿·폴더블·PC 배치, 셔플·부채꼴 모션·버튼 위치·글 내용·이미지·음악을 변경하지 않는다.
- 새 CSS 덮어쓰기/기기 전용 레이아웃 추가 없이 **기존 단일 계산 파일 `js/settings/config/config.js`만 수정**한다.
- 이전 아이패드 미니 결과 카드 높이 제한은 보존한다.

## 확인된 문제
1. 700px 세로 터치 분기: 699×1024에서 결과 카드 287.01px이 700×1024에서 256.58px로 줄어드는 역전. 화면이 좁아질 때 카드가 커지는 현상도 같은 원인.
2. 공통 글자·버튼·화살표 배율: 스마트폰 기준 390×844에서 1배, 700×1024에서 0.8537배로 감소하며 화면과 반대 방향으로 변화. 기준 기기가 바뀌는 순간 발생.
3. 터치 가로에서도 컴팩트(높이 599px)에서 태블릿형(600px)으로 넘어갈 때 배율이 감소. UI 배율은 연속화하되 각 레이아웃의 기존 카드 무대 높이 제한은 보존.

## 적용 방식
- 터치 화면의 제목·설명·버튼·화살표 배율은 화면 면적을 사용하는 **한 가지 연속 함수**로 통합한다. 기준 390×844에서 1배, 큰 화면까지 완만하게 상승, 기존 최소/최대 제한 유지. 가로·세로 어느 하나가 커져도 공통 배율이 감소하지 않는다.
- PC는 기존 `min(너비/1366, 높이/768)` 계산과 기존 UI 배치를 그대로 사용한다.
- 세로 터치 **결과 카드 크기**는 승인된 휴대폰 390px 기준값과 기존 태블릿 700px 기준 계산값 사이를 부드럽게 연결한다. 카드 너비가 700px 경계에서 역전되지 않는다. 700px 이상 기존 태블릿의 결과 크기 계산 및 아이패드 미니 보정은 보존.
- 매우 낮은 세로 화면에서 태블릿 기준 크기가 휴대폰 기준보다 작은 경우에도 결과 카드 너비가 역전되지 않도록 연속 하한을 적용한다.
- 카드뭉치·첫 셔플·중간 모션·부채꼴·공개 이동의 원본 코드·애니메이션 시간은 수정하지 않는다. 기존 배치가 바뀌는 지점에서는 무대 가용 높이에 따른 단계별 크기 변화가 남아 있을 수 있다.

## 검증
- 수정 파일 JavaScript 구문 검사: 통과.
- 정적 계산 대조: 세로 화면 높이 11종 × 가로 너비 320~1199px, 세로 화면 너비 10종 × 높이 500~1499px 인접 값 변화 검사. 카드 단계별 크기·UI/버튼/화살표 배율의 **축소 화면에서 확대되는 역전 0건** (해당 검사 조건).
- 390×844 휴대폰 기준 카드/배율, 768×1024·744×1133·820×1180·1024×1366 결과 카드 너비, PC 1366×768 및 1440×900 전체 수치 비교: 유지.
- 699×1024 결과 카드: 287.01→256.36px, 700×1024 결과 카드: 256.58→256.58px. 같은 경계에서 공통 배율 1.09770→1.09789로 연속 증가.
- 768×1024 아이패드 미니: 결과 카드 너비 279.19px 유지, UI 텍스트 배율 0.8678→1.1102. 따라서 **실제 글자·버튼 표시 크기는 달라질 수 있다**. 이는 공통 비례 설계 통합의 의도된 변경이다.
- 터치 가로의 599→600px **부채꼴 카드 무대 높이 제한**에서 약 3px 축소는 아직 남음. 이미 승인된 모션/클리핑 여유를 침범하지 않도록 이번에는 무대 계산을 임의 조정하지 않았음. 방향 전환 직전/직후 결과 카드 크기는 서로 다른 배치이므로 연속 수치로 간주하지 않음.
- 실제 브라우저 전체 과정·실기기 검사: **미완료**. 이 환경은 file:// 로컬 브라우저 접속 시 `ERR_BLOCKED_BY_ADMINISTRATOR`. 정적 검사 통과를 실화면 검증 완료라고 표시하지 않는다.
