## 1. 사용자가 승인·요청한 설계 (기존 기록과 이번 대화)

- 화면 여백: 상·하·좌·우 **각 4%**의 공통 기준을 지향한다. 단, 이미 만족한 기존 제목·카드·본문·버튼 위치를 임의로 옮기지 않는다. 현재 CSS 위치 수치를 일괄 4%로 교체하지 않았다. 향후 디자인 검증을 거쳐 위치를 유지하는 범위에서 적용.
- 기존 스마트폰 세로·가로 배치와 접힘·펼침 폴더블의 적용 경로 보존. 모바일 가로의 **오른쪽 아래 버튼**, 태블릿 가로의 **하단 중앙 버튼**, PC의 기존 결과 배치를 구분한다. 태블릿/폴더블에 PC형 공통 배치를 확대 적용하자는 후속 아이디어는 기존 사용자가 만족한 위치와 충돌할 수 있으므로 승인된 배치의 무단 전환을 하지 않는다.
- 카드뭉치·셔플·계단/3D 궤도·부채꼴·선택·공개·앞면 카드·상단 제목·설명창·본문 글자·버튼·버튼 글자·화살표·빛 효과는 장기적으로 같은 실제 사용 공간과 비례 체계에 연결한다. 기기 모델별 예외값/새 CSS 덮어쓰기 추가를 피한다.
- 첫 셔플: 움직임은 화면 밖으로 나가도 된다. 화면에 넣으려고 궤도를 좌우/상하 다르게 찌그러뜨리지 않는다. 기존 첫 셔플의 안무·속도·장면을 이번 ZIP에서 바꾸지 않는다.
- 정착한 부채꼴·선택 카드와 최종 결과 카드의 글/버튼 입력 가능 영역은 보호한다. 첫 선택은 원래 카드 크기 유지 + 위로 22px, 공개 이동 중 최종 결과 크기로 변화한 다음 뒤집는다.
- 부채꼴: 무한 순환형 드래그가 시각적으로 이어져야 하며 카드 아래 끝이 안쪽으로 몰려 답답해 보이는 문제가 있다. **PC 원본 부채꼴의 간격·각도·높이차 자체는 사용자가 만족**한다.
- 기록된 개별 시험 선호치: 모바일 세로 21° / 카드 중심 간격 125% / 양끝 높이차 50%, 모바일 가로 20° / 85% / 50%, 태블릿 세로·가로 23° / 98% / 30%. 이후 사용자가 PC 원본 기하를 전 기기에도 비례 적용하자고 제안했고 비교를 원했다. 따라서 위 선호치는 잠정이며, 이 수정본에 어느 쪽도 독단적으로 강제 적용하지 않았다.
- 본문·상단 제목·버튼 글자·화살표 크기는 함께 평가해야 한다. 기존에 만족한 위치와 글의 내용은 보존한다.

## 4. 적용하지 않은 설계·미완료 항목

1. 4% 여백을 기존 상단 제목·버튼 위치까지 전부 강제하는 CSS 일괄 재배치 (사용자가 현재 위치에 만족한 만큼 별도의 시각 비교 필요).
2. PC 원본 부채꼴 기하를 모바일·태블릿·폴더블 전체에 동일 적용 (비교/확정 이전의 아이디어). 또는 기기별 잠정 수치를 실제 코드에 곧바로 강제하지 않았다.
3. 첫 셔플·계단·3D 원근을 단일 카드 기준 배율로 전면 재작성 (기존 안무 보존, 실제 모션 비교 부재).
4. 상단 문구·결과 글·버튼 글자·안내 화살표의 공통 타이포그래피 스케일 (기존 만족한 위치와 손가락 입력 크기 확인 후).
5. 셔플 중 회전 시 현재 포즈와 새 경로를 연속으로 이어 붙이는 일 (이번에는 결과 상태의 갱신만 수정).
6. 마법 캔버스·금빛 효과를 새 크기 계산값으로 통합하는 일 (카드와 조명 시각 동기화 미검증).
7. 기존 CSS 덮어쓰기 순서의 전체 정리 및 44개 미디어 조건 통합 (무단 삭제/중복 기능 손상 방지).

## 5. 검증 상태·한계

- 변경된 JS 파일의 `node --check` 구문 검사는 통과.
- 화면/조건 모의 테스트에서 390×844, 844×390, 820×1180, 1180×820, 1000×550, 1440×900, 1440×500의 단계별 크기가 유한한 양수인지 확인. 실제 viewport stage 계측을 대신하지 않는다.
- 이 세션의 Chromium/Playwright에서는 로컬 `127.0.0.1` 및 `file://` 접속 모두 `ERR_BLOCKED_BY_ADMINISTRATOR`로 실패. **따라서 수정본 전체 흐름·화면 검증을 완료했다고 주장하지 않는다.**
- 차후 실제 브라우저에서 29조건 + 높이만 변경 + `revealing` 중 회전 + 폴더블 깊이 + 카드 클릭 영역과 제목/버튼 겹침 검증이 필요하다.
