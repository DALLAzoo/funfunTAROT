# 설정과 실행 안내

주요 설정 파일은 `js/config.js` 한 개다. 별도 UI 설정 화면은 추가하지 않았다. 변경 후 페이지를 새로고침한다.

## 실행

ZIP을 새 폴더에 풀고 그 폴더에서 아래 명령으로 연다.

```sh
python -m http.server 8768
```

브라우저 주소: `http://127.0.0.1:8768/`.
ES 모듈이므로 파일 더블클릭 대신 HTTP로 실행한다. 추가 패키지 설치는 필요 없다.

## 단계별 크기

`CONFIG.sizes`의 값은 CSS px 단위의 물리적 기본 너비다. 높이는 aspect 비율로 계산한다. perspective 때문에 화면에서 보이는 너비는 달라진다.

| 단계 | PC | 모바일 | 위치 |
|---|---:|---:|---|
| 셔플 | 164 | 104 | sizes.desktop/mobile.shuffle |
| 선택 | 210 | 146 | sizes.desktop/mobile.selection |
| 전환 카드 기본 크기 | 240 | 160 | sizes.desktop/mobile.transition |
| 결과 | 260 | 190 | sizes.desktop/mobile.result |

한 단계의 값을 바꾸면 그 단계만 사용한다. 전환 카드의 기본 크기를 바꿔도 화면 덮기는 viewport 실측으로 다시 계산한다. 모바일 구분 폭은 breakpoint=600이다.

선택 화면의 카드 간격은 회전한 가장자리 폭·원근감·표시 수·무대 폭을 반영해 자동 계산한다. 큰 값이나 많은 표시 수에서는 카드가 많이 겹칠 수 있다. 모든 장수·크기에서 같은 미적 품질을 보장하지 않는다.

## 장수와 자산 수

```js
counts: { shuffle:22, selection:20, visible:3, result:1 }
```

- shuffle: 공중 연출에 사용하는 카드 수. 현재 등록 데이터 수 이하여야 한다.
- selection: 순환 탐색 대상 수. shuffle과 독립이다.
- visible: 동시에 보이는 카드 수. 이번 구현은 3 또는 5를 지원한다.
- result: 이번 공개 흐름은 1장을 지원한다. 2장 이상은 검증 오류로 막는다. 여러 장 결과는 별도 상태 흐름 확장이 필요하다.
- 실제 등록 카드 데이터 수와 앞면 이미지 수는 catalog에서 계산한다. 수만 늘려 파일이 존재하는 것처럼 표시하지 않는다.

현재 데이터 22장·실제 앞면 이미지 등록 0장·뒷면 8종이다. 앞으로 보관할 78장과 선택 대상 20장은 별개다. 최대 78개의 고유 카드 데이터를 처리하도록 구조를 준비했지만 실제 78장 자산 검증은 하지 않았다.

## 20장 구성

초기값 `pool.mode:'trial-uniform-subset'`는 시험용이다. 전체 데이터에서 무작위로 서로 다른 20장을 고른다. 고정 제외 카드가 없으며 최종 정책을 뜻하지 않는다.

명시된 목록을 사용하려면:

```js
pool: {
  mode:'explicit-ids',
  ids:[/* 승인된 선택 대상 ID를 selection 수만큼 입력 */]
}
```

중복 ID·없는 ID·장수 불일치는 오류로 막는다. 카드 ID는 메이저 순서대로 major-00~major-21이다.

## 앞면 이미지 등록

원본 이미지를 `assets/card-fronts/` 등에 놓고 config.js에 해당 ID의 경로를 등록한다.

```js
catalog: {
  additionalCards: [],
  frontImages: {
    'major-00':'./assets/card-fronts/major-00.png'
  },
  requireActualFrontImages:false
}
```

미등록 카드에는 이름·기호 시연과 미등록 안내가 나온다. 등록한 URL이 로딩·decode에 실패하면 선택 화면으로 복구하고 오류를 알린다. 다른 카드 이미지를 대신 보여주지 않는다.

`requireActualFrontImages:true`는 등록 데이터 전체에 앞면 URL이 있는지 검증한다. URL이 적혀 있다고 파일 존재까지 보장되지는 않으며 실제 이미지 해독 검사는 해당 카드 선택 시 수행한다.

새 카드 데이터는 `catalog.additionalCards`에 `{id,name,symbol}` 형태로 추가하고 frontImages에 경로를 연결한다. 기존 ID를 바꾸면 결과·이미지 연결도 달라지므로 고유 ID를 유지한다.

## 동선·속도·두께·빛

| 설정 | 의미 |
|---|---|
| camera.perspective | 작을수록 깊이에 따른 크기 차이가 강해짐 |
| shuffle.radiusX/radiusY | 무대 폭/높이에 대한 이동 범위 |
| shuffle.nearDepth/farDepth | perspective에 대한 전경/후경 깊이 비율 |
| shuffle.turns | 궤도 이동량 |
| shuffle.duration/separate | 셔플·초기 분리 시간(ms) |
| finale.duration/pressure/afterglow | 파동 펼침 시간·가속감·잔광 시간 |
| carousel.gap/angle/drop | 간격·최외곽 각도·곡선 높이 |
| carousel.move/enter | 순환 이동·새 카드 진입 시간 |
| material.thickness | 얇은 측면 레이어 깊이(px) |
| material.shadowY/shadowBlur/shadowAlpha | 그림자 |
| material.edge/satinEdgeAlpha | 측면 색과 가장자리 반사 |
| glow.enabled/rgb/intensity/blur | 외곽 발광 사용·RGB·강도·폭 |
| glow.pulseMs | 외곽 빛 맥동 주기(ms) |
| glow.centerEmphasis/centerMultiplier | 중앙 카드 강조 여부·배수 |
| glow.dragMultiplier | 드래그 중 발광 강도 |
| reveal.lift/focus/approach/arrival/flip | 부상·집중·화면 덮기·결과 도착·뒤집기 시간 |
| reveal.overscan | 덮기 여유 배율 |
| reveal.mode | 공개 방식 비교 |

공개 방식 기본값 `flip-after-arrival`은 결과 위치에 도착한 뒤 뒤집는다. 대안 `front-on-arrival`은 결과 위치로 들어오는 동안 뒤집어 앞면으로 도착한다. PC 검사에서 두 방식 모두 결과 도착을 확인했다. 최종 채택은 미확정이다.

## 검증 범위

숫자·장수·중복 ID·지원 표시 수·결과 수·크기·원근감·깊이·시간·일부 재질 범위를 검사한다. support 항목은 구현된 기능 범위를 적은 내부 기준이다. 이 목록을 바꾼다고 기능이 자동 확장되는 것은 아니다.

실제 보유 데이터보다 많은 장수는 막는다. 3/5장 표시, 기본 PC/모바일 크기와 16장 셔플/22장 풀의 설정 변경을 확인했다. 임의의 모든 조합에 같은 품질을 보장하지 않는다.
