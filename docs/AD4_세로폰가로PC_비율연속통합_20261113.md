# AD4 — 세로 스마트폰 기준 / 태블릿 가로 PC 기준 비율 통합

기준 시험본: `InBetweenShift_AD4_방향별비율통합_전체시험본_20261113.zip`  
상태: **시험본 / 계산 및 CSS 부분 검증 완료 / 실제 사이트 전 흐름 미검증**

## 목적

기존 배치와 기능을 그대로 두고, 세로는 스마트폰 세로 디자인, 태블릿 가로는 PC 가로 디자인의 **상대적 크기**를 기준으로 삼는다. 기준 원본 ZIP, GitHub 및 배포 수정 없음.

## 수정 내용

1. **태블릿 세로:** `css/screen/23-portrait-responsive-scale.css`의 기존 결과 설명창 너비 규칙에서 `--portrait-reading-width`를 사용한다. 기본 세로 디자인은 기존 520px 제한을 유지하고, 터치 세로는 `#resultView` 자체에서 카드 크기 `--result-width`에 비율 `358/190`을 곱한 값을 전달한다. 이 방식은 기존 규칙을 연결하며 새로운 파일을 덮어씌우지 않는다.
2. **태블릿 가로:** `js/settings/config/config.js`의 기존 태블릿 결과 카드 계산을 변경한다. PC 원본 1366px 가로 화면의 실제 좌측 열 크기 대비 결과 카드 너비(260/약 614.7 = 약 42.3%)를 태블릿 가로의 **좌측 영역**에 적용한다. 제목/버튼을 고려한 기존 높이 제한은 계속 적용한다.
3. 카드 이미지의 가로세로 비율 `2128/1240`, 첫 셔플/부채꼴/선택/공개 모션, 배치 구조, 메뉴와 리딩 원문, 이미지·음악 파일은 그대로 유지한다.

## 검증 / 미검증

- `node --check` JS 문법 통과.
- JS 단계별 계산: 14개 화면 × 5단계 비교. **결과 카드 크기가 달라진 경우는 태블릿 가로 4건뿐**. 스마트폰 세로/가로, 태블릿 세로, PC와 카드뭉치·셔플·선택·이동의 수치는 기존과 같았다.
- Chromium에 원래 CSS 불러오기 순서대로 전체 스타일을 주입한 결과 화면 모의 DOM 검사: 699/700px 포함 검사 화면에서 설명창·버튼의 화면 경계 밖 이탈 없음, 제목–카드–설명·버튼 배치 규칙 유지.
- **실제 사이트 전체 URL 실행은 이 환경에서 브라우저 보안 차단(`ERR_BLOCKED_BY_ADMINISTRATOR`)으로 진행할 수 없었다.** 모의 CSS 검사는 전체 애니메이션 실동작 검증이 아니다.
- 실제 태블릿 세로(특히 iPad mini / Surface Pro), 가로(특히 iPad mini / Pro)와 화면 회전 및 첫 셔플→부채꼴→선택→공개 구간의 실기기 시각 검증은 추가로 필요하다.
